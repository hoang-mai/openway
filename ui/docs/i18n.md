# Internationalization (i18n) in OpenWay UI

> **Enterprise-grade, zero-dependency localization for React 19, Next.js, and modern frontends.**

`@openway/ui` comes with built-in internationalization support modeled after enterprise design systems. It requires **zero external runtime dependencies** (under 1KB bundle footprint) while remaining 100% type-safe and fully compatible with popular i18n frameworks like `next-intl`, `react-i18next`, and `react-intl`.

---

## 1. Quick Start

By default, `@openway/ui` displays all technical labels, aria-labels, and fallback texts in **English (`enUS`)**.

```tsx
import { Button } from "@openway/ui/button";

// Works out of the box in English without any configuration
export default function App() {
  return <Button>Submit</Button>;
}
```

### Switching to Vietnamese (`viVN`)

To localize the entire UI library into Vietnamese, wrap your root application or layout with `<OpenWayProvider>`:

```tsx
// app/layout.tsx
import "@openway/ui/styles.css";
import { OpenWayProvider, viVN } from "@openway/ui/locale";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="vi">
      <body>
        <OpenWayProvider locale={viVN}>
          {children}
        </OpenWayProvider>
      </body>
    </html>
  );
}
```

## 2. Priority Hierarchy (Cascading Overrides)

`@openway/ui` resolves rendered text through a 3-tier hierarchy:

$$\text{Direct Component Prop} \;\;>\;\; \text{OpenWayProvider Context} \;\;>\;\; \text{Default Locale (enUS)}$$

If you supply a prop directly to a component, that prop **always takes precedence**:

```tsx
import { OpenWayProvider, viVN } from "@openway/ui/locale";
import { ConfirmFooter } from "@openway/ui/confirm";

export function CustomConfirm() {
  return (
    <OpenWayProvider locale={viVN}>
      {/* Defaults to "Xác nhận" and "Hủy" from viVN */}
      <ConfirmFooter />

      {/* Override button text locally */}
      <ConfirmFooter confirmText="Đồng ý xóa" cancelText="Giữ lại" />
    </OpenWayProvider>
  );
}
```

## 3. Dynamic Language Switching

You can switch the active locale dynamically at runtime by changing the `locale` state:

```tsx
"use client";

import { useState } from "react";
import { OpenWayProvider, enUS, viVN } from "@openway/ui/locale";
import { Button } from "@openway/ui/button";
import { ConfirmFooter } from "@openway/ui/confirm";

export function LanguageSwitcherDemo() {
  const [currentLocale, setCurrentLocale] = useState(enUS);

  return (
    <OpenWayProvider locale={currentLocale}>
      <div className="flex gap-2 mb-4">
        <Button size="sm" onClick={() => setCurrentLocale(enUS)}>
          English
        </Button>
        <Button size="sm" onClick={() => setCurrentLocale(viVN)}>
          Tiếng Việt
        </Button>
      </div>

      <ConfirmFooter />
    </OpenWayProvider>
  );
}
```

## 4. Custom Locale Dictionaries (e.g. Japanese, French, German)

You can create custom language packs with complete TypeScript auto-completion and compile-time validation by importing the `OpenWayLocale` interface:

```tsx
import type { OpenWayLocale } from "@openway/ui/locale";
import { enUS } from "@openway/ui/locale";

export const jaJP: OpenWayLocale = {
  ...enUS, // Fallback missing keys to English
  locale: "ja-JP",
  confirm: {
    confirmText: "確認",
    cancelText: "キャンセル",
  },
  table: {
    ...enUS.table,
    searchPlaceholder: "テーブル内を検索...",
    clearSearch: "検索をクリア",
    refresh: "データを更新",
    columns: "列",
    columnVisibility: "列の表示設定",
    rowsPerPage: "件数/ページ:",
    emptyText: "データがありません",
    emptyFilteredText: "該当するデータが見つかりません",
  },
  empty: {
    description: "データがありません",
  },
  upload: {
    ...enUS.upload,
    dragDropText: "ここにファイルをドラッグ＆ドロップ、またはクリックして選択",
    browseButton: "ファイルを選択",
    cropTitle: "画像を切り抜く",
    cropConfirm: "適用",
    cropCancel: "キャンセル",
  },
};
```

## 5. Integration with Next.js & `next-intl`

If your consumer application uses `next-intl` for routing and translations, connecting it with `@openway/ui` is seamless:

```tsx
// app/[locale]/layout.tsx
import { ReactNode } from "react";
import { OpenWayProvider, enUS, viVN } from "@openway/ui/locale";

const localeMap = {
  en: enUS,
  vi: viVN,
};

export default async function LocaleLayout({
  children,
  params,
}: {
  children: ReactNode;
  params: Promise<{ locale: string }>;
}) {
  const { locale } = await params;
  const activeLocale = localeMap[locale as keyof typeof localeMap] || enUS;

  return (
    <html lang={locale}>
      <body>
        <OpenWayProvider locale={activeLocale}>
          {children}
        </OpenWayProvider>
      </body>
    </html>
  );
}
```

## 6. Components Covered by i18n

| Component | Localized Elements |
| :--- | :--- |
| **`Table` / `DataTable`** | Pagination ("Rows per page:", "First page", "Previous page", "Page N"), search input placeholder, clear search, refresh tooltip, column visibility toggle, and empty state fallbacks. |
| **`Confirm`** | Confirm button ("Confirm"), Cancel button ("Cancel"). |
| **`Empty`** | Default empty description ("No data"), image alt. |
| **`CheckboxGroup` / `RadioGroup`** | Search placeholder ("Search..."), empty options notice ("No results found"). |
| **`Select`** | Option search placeholder, empty state. |
| **`UploadFile` / `UploadImage`** | Drag & drop notice, file browse button, upload progress, file size validation errors, unsupported format error. |
| **`UploadAvatar`** | Avatar crop modal title ("Crop image"), zoom control, rotate controls, reset button, confirm and cancel buttons. |
| **`DatePicker` / `DateRangePicker` / `DateTimePicker`** | Month names, weekday abbreviations, today button, clear button, and navigation buttons. |
| **`useMutationApp`** | Default error toast title and HTTP status code messages (400, 401, 403, 404, 409, 422, 500, network error, timeout). |
